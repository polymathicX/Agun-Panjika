\ReportPage{The problem and the experience}{sec:experience}
\begin{keypoint}{Two questions, with different kinds of evidence}
What are satellites observing in my country now? How can we compare fire activity when the observing instruments change?
\end{keypoint}
MODIS and VIIRS have different resolutions and sensitivities. NASA FIRMS provides MODIS active-fire pixels at about 1\,km and VIIRS at 375\,m. Joining raw counts can make an instrument change look like a change in burning. Detections are not unique fires, burned area or a direct measure of human exposure.

Agun Panjika combines a place-based observation viewer with an inspectable historical sensor correction. It preserves the textured Soft Earth interface while extending the Bangladesh prototype to worldwide recent observations and four historical evaluation areas.

\subsection{A short user journey}
An optional first visit teaches the main controls. Explain this page offers 85 English/Bangla help topics across all nine views. Short readings explain each selection, with the source basis and interpretation limits available alongside it.
\begin{enumerate}
\item \textbf{Choose a place.} Spin and zoom the 3D Earth, then tap a country. A keyboard selector and flat map provide alternatives. Reduced-motion preferences are respected.
\item \textbf{Read the present.} Select MODIS, NOAA-20 or NOAA-21, compare days and play the timeline. The source window and snapshot date stay visible.
\item \textbf{Inspect the past.} In a supported historical area, change the sensor-switch week, compare raw/factor/model curves and reveal the real VIIRS reference.
\item \textbf{Keep the evidence.} Save a country locally or export a dated PNG, JSON or daily CSV. Historical briefs also support print/PDF.
\end{enumerate}

\subsection{From observations to a record}
The Python pipeline normalizes source fields and confidence, assigns geography, filters observations, aggregates ISO weeks, fits the correction and baselines, handles successor continuity and exports calendars, seasonal summaries and evidence packages. The frontend reads static exports; no application backend or database is required.

The worldwide seven-day viewer uses fixed confidence rules. It does not add overlapping satellites into a unique-fire total. Summary counts use all retained rows; point rendering is capped and sampled. Some industrial heat can remain. Per-source windows and SHA-256 hashes accompany the exports.

\subsection{Continuity and observation completeness}
Shared monthly successor-factor and handover/outage functions now serve national, local and neighbour series. A real zero participates; a missing sensor does not. Map points select the source for the chosen ISO week, including within-year handover. Bridge bounds survive export. Tests cover nonidentity factors, zeros, absent sources and switch boundaries.

Requested API chunks fail explicitly on retrieval failure and stop at each source's declared availability, including S-NPP retirement. These fixes prevent silent zero chunks, but historical sensor-span zero filling does not prove clear-sky coverage or complete daily retrieval.

\begin{keypoint}{Scale matters}
Early local CHT values include apportioned estimates. Arbitrary polygons cannot inherit validated reconstruction merely from an interactive drawing tool. Worldwide recent-data access is distinct from worldwide calibrated historical accuracy.
\end{keypoint}

\ReportPage{Model, evaluation and complete results}{sec:evidence}
\subsection{Annual past-only reconstruction}
The detector-only ensemble combines 30\% negative-binomial regression and 70\% five-seed LightGBM. A strict guard replaces the tree contribution by a fitted factor only above the pooled training MODIS maximum, supporting estimates beyond the fitted tree range.

For target year \(Y\), fit on 2013 through \(Y-2\), calibrate intervals on \(Y-1\), then evaluate \(Y\). Thus the 2022/2023/2024 fits end in 2020/2021/2022. Each year uses only older labels. Following-week MODIS features make this retrospective reconstruction, not forecasting. The years were known during development: this is not an untouched final holdout.

\subsection{How to read the seasonal example}
The Nepal example connects a MODIS-based reconstruction to later VIIRS observations. Revealing the reference makes it possible to inspect the seasonal shape directly. The app also provides a plain-language reading for the selected year and switch week. Detailed tables retain every model and source-quality flag.

NASA acquisition outages make 14 test weeks incomplete. The same quality rule applies to all areas and baselines; raw values and all-week scores remain public. Comparable-week totals are not full annual totals. Earlier historical estimates use the latest vintage, fit 2013--2022/calibrate 2023.

\ReportPage{Reproduction, architecture and delivery}{sec:delivery}
\begin{keypoint}{A mentor can refit the public experiment without a NASA key}
\texttt{python -m pip install -e ".[dev]"}\par
{\footnotesize\texttt{python -m pipeline.global\_cases --from-packages}}
\end{keypoint}
Compact public feature CSVs include region-week detector inputs and VIIRS labels. Each file has a checksum and row count. The command refits models, calibration and scoring and reproduced all four published evaluations in the release environment. This is not an independent raw-to-feature audit; library/platform variation is possible. Raw regeneration uses the pipeline and documented upstream sources.

\subsection{A static deployment with separate refresh}
React/TypeScript, Three.js, D3 and MapLibre render versioned exports. The service worker provides offline reference access. GitHub Pages publishes the application. A six-hour workflow refreshes public global feeds separately from heavier scientific regeneration; failed retrieval does not silently become an empty successful snapshot. Hosted global refresh and deployment have succeeded. The full heavier science workflow is not claimed as reverified in hosted CI.

The browser receives no FIRMS secret. Optional API keys stay in the ignored root environment or CI secrets. A watchlist stays on the device. Original code is Apache 2.0; third-party maps, textures and software retain their terms. Dependency notices are generated at build time.

\subsection{Verification and its limits}
The release checks cover 80 Python scientific/unit/export cases, TypeScript/build, frontend evidence tests, and 14 browser groups including globe controls, country selection, exports, failure recovery and offline behavior. The responsive matrix covers nine routes in six viewport/theme/language combinations: 54 views. Current counts, CI evidence and reproduction commands are recorded in the linked verification report.

Chromium installability and emulated phones are checked. These do not establish physical iPhone/Android behavior, complete accessibility certification, measured field usefulness or prospective forecast skill. Zero dependency advisories reflects the release audit, not a general security guarantee.

\subsection{Presentation package}
Seven English slides and a captioned 29-second video show actual application captures, interaction footage and plotted results. AI assistance is visibly acknowledged and source credits are retained. There is no synthetic narrator. The old 2:42 local video is background material, not the global short demo.

\ReportPage{Academic questions and intended benefit}{sec:review}
\subsection{What people could use it for}
A student can investigate observations in their own country. A community group can share a dated source brief. A researcher or land manager can inspect seasonal patterns and sensor discontinuities. These are supported tasks, not measured adoption or prevention outcomes. The prototype is not an emergency warning service.

\begin{keypoint}{Evidence we have not created}
No completed practitioner pilot, agency adoption, fires prevented or lives saved is claimed. A polished interface does not substitute for blind labels, an untouched evaluation or prospective observations.
\end{keypoint}

\subsection{Where mentorship would help most}
\begin{enumerate}
\item \textbf{Evaluation design.} Agree a new locked temporal/geographic test and primary metric, with preprocessing and calibration fitted only on allowed partitions.
\item \textbf{Scientific interpretation.} Review the support guard, annual fitting and Chin's stronger monthly baseline. Which seasonal comparisons, ablations and spatial scales should a new evaluation test?
\item \textbf{Uncertainty and filtering.} Design blind industrial-source labels, retained-fire sensitivity checks and interval assessment across season/activity/sensor regimes.
\item \textbf{Practical use.} Recruit a remote-sensing practitioner or land manager for a small comprehension/workflow study, using the existing task protocol and observed interpretation errors.
\end{enumerate}

\subsection{What would support stronger future claims}
Prospective outlook validation needs archived issue-time weather, rolling-origin fits, independent calibration and honest baselines. Observed-future-weather experiments cannot establish operational skill. Wider historical geography and arbitrary polygons require evaluation at their intended scale. Physical-device and assistive-technology checks should accompany a field pilot.
